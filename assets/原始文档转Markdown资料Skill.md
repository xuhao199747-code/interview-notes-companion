# 原始文档转 Markdown 资料 Skill

## 目标

将用户提供的飞书文档、会议纪要、项目文档、个人笔记、Word、PDF、网页导出文本和表格内容，转换为**完整原文可追溯**的 Markdown 资料库。整理只负责分类、增加检索入口和把非文本信息转成文字描述；不得把资料压缩成摘要或替换成改写稿。

## 同步前检查

1. 读取当前原始文档，记录资料标题、来源链接、文档 token、修订号/读取时间和原文字符数。
2. 若资料来自飞书，先拉取当前完整版本；有嵌入表格、电子表格、多维表格、画板、附件或图片时，继续读取其中可提取的文字或结构，不能只保留一个链接或占位标签。
3. 与当前本地资料的“当前飞书版本”比较。先确认是新增、同版本重复导入还是新修订，不得凭标题相同直接覆盖。

## 原文保真规则

1. **完整原文必须保留**：每一个已有标题、问题、逐字稿、回答、备注、待确认项、列表、表格文字、数字、日期、专有名词、引用和重复段落都保留。重复本身可能代表不同版本、不同语境或用户刻意保留，禁止删除。
2. **不得改写**：不得润色、概括、合并同题回答、补写结论、调整事实语气或把原文替换为“更好读”的版本。允许只做无语义变化的 Markdown 转义、空白修复和标题层级修复。
3. **不得删除**：只有纯页面导航、空白块或确认与正文无关的系统噪声可以移除；若不确定，保留并标为“原文格式/待确认”。
4. **图片、图表和流程图必须文字化**：保留图表原有标题、字段、节点、连线方向、条件、指标、结论和图中备注；不能读取时写明“图片/图表待人工补录”，并保留其原始位置和可访问引用。不得因为图表无法解析而删掉其周边说明。
5. **表格不得只留关键字段**：转换为完整 Markdown 表格；无法稳定还原布局时，逐行保留所有单元格文字，并注明原表结构。
6. 可以额外添加“检索索引”或“分类标签”，但必须与原文分离，且每个索引项都能回到原文中的明确标题或段落；索引不能替代原文。

## 版本与来源规则

1. 每份本地资料顶部写入来源链接、文档 token、当前修订号/读取时间、当前原文字符数和资料归类。
2. 新修订版写入 `## 当前飞书版本（修订号/读取时间）`；旧版移动或保留在 `## 历史飞书版本` 下，保留原文完整快照和对应修订信息。
3. 新版本中缺失的旧内容不视为可以删除；保留历史快照并说明“当前飞书版本未出现，历史保留”。
4. 同一题存在多个版本时，分别保留，禁止合并成一个“最佳答案”；当前版本可在标题旁标记，但不得覆盖历史原文。
5. 输出完成后记录：原始文档字符数、本地当前版本字符数、历史快照数量、图表/图片待补录数量。若字符差异无法解释，停止同步并报告差异，不上传不完整版本。

## 输出格式

```markdown
# 资料主题

> 资料归类：通用问题 / 项目资料 / 技术专题 / 其他
> 来源：<原始链接>
> 文档 token：<token>
> 当前飞书修订：<revision_id 或读取时间>
> 原文字符数：<数量>

## 检索索引（非原文）

- <题目或主题> → 当前飞书版本 / 原文标题

## 当前飞书版本（修订 <revision_id>）

<完整原文；仅作 Markdown 格式转换>

## 历史飞书版本

### 修订 <revision_id/读取时间>

<历史完整原文快照>

## 图表与图片文字说明

<按原位置记录可读内容或待补录状态>

## 同步核对

- 原文字符数：
- 当前本地版本字符数：
- 历史快照数：
- 图表/图片待补录数：
- 未解释差异：无 / <说明>
```

仅在原始资料实际存在对应内容时创建栏目；不要凭模板编造项目背景、结果或指标。同步后直接上传更新后的 Markdown 到 APP 资料库，并保留本地文件与 APP 内容一致。
