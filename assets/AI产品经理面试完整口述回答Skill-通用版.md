# AI 产品经理面试完整口述回答 Skill（通用开源版）

## 目标

把已确认的资料组织成面试中可直接说出口的回答。Skill 只规定组织方式、口语表达与事实边界；具体项目、公司、个人经历、资料链接和数据只从本机私有资料读取，不能写入本文件。

## 回答原则

1. 先判断题目属于经历、项目、追问、通用方法论、外部产品分析还是术语定义。
2. 命中原文时，优先保留原文的事实、顺序、数字和可口述表达；只做不改变原意的断句、去重和格式调整。
3. 未命中原文时，明确区分已确认事实与建议做法。通用题使用“可以、建议、我会”，不编造成候选人的经历。
4. 项目题只使用当前锁定项目的本地资料，不能跨项目拼接数据、职责或结果。

## 资料与追问

- 资料原文是事实来源；Skill、术语表和回答规则不作为项目事实来源。
- “这个项目、你们、它、指标怎么算、具体怎么做”等指代性问法，沿用最近已确认的项目；题目明确点名新项目时立即切换。
- 原文没有结论、数字或结果时，直接说明需要本人确认，不补造。

## 口述结构

- 概念题：先一句定义，再说明解决的问题、核心机制、适用边界和一个简短例子。
- 项目题：按业务问题、用户或使用场景、产品做法、关键技术与取舍、指标或验证结果展开。
- 技术架构题：按“收到什么任务 → 调用哪些工具或能力 → 关键设计与判断 → 输出什么结果 → 如何评测和兜底”讲清链路；技术名称要说明在当前任务中负责什么、为什么需要它。
- 给定业务场景的开放题：先讲用户背景、具体场景和未被满足的痛点，再讲产品目标、方案、验证方式；术语定义和已有原文的具体做法直接回答核心问题。

## 表达要求

- 先直接回答，不复述题意、不解释面试官考察点、不讲系统内部判断过程。
- 默认使用 3—5 个短段落；每段只讲一个重点，让场景、做法和技术自然连在一起。
- 首次出现必要英文术语时，在括号内补中文解释；不要堆砌技术名词。
- 遇到高风险、低置信度或需要人工确认的信息，明确说明规则、模型与人工的分工，以及拒答、人工接管或审计边界。

## 输出前检查

1. 每个项目事实都能回到本机原文。
2. 通用方法论没有伪装成个人经历。
3. 没有混入其他项目、陌生产品或无关案例。
4. 有原文时优先原文；没有原文时不虚构。
