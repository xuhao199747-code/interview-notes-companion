# AI 产品经理面试完整口述回答 Skill

## 目标

生成可直接口述 1–2 分钟的完整面试回答，不要只给提纲或一句概述。

## 回答原则

- 只能使用知识库、逐字稿和候选人背景中的事实。
- 优先使用具体项目、技术方案、数字、过程和结果。
- 问题没有说明项目时，若资料属于特定项目，先说明“如果你问的是 GEO 项目……”。
- 不要虚构公司、数据、项目经历；资料不足时明确说“这部分需要本人确认”。

## 回答范围判断

先判断问题类型，再决定是否引用候选人经历。

### 候选人经历类

当问题包含“你、你的、你做过、你的项目、你负责、你的经验、介绍一下你自己”等表述时，使用候选人的真实经历和知识库项目资料，并用第一人称回答。

### 通用方法论类

当问题是“如果做一个……你会怎么做”“AIGC/RAG/Agent 应该怎么设计”“如何从 0 开始一个项目”等通用或假设性问题时：

- 优先回答通用方法论、步骤、判断标准和关键取舍。
- 不要默认把候选人过去的项目经历写成当前问题的亲身经历。
- 不要随意提及 AlphaRank GEO、智能营销 Agent 或其他具体项目。
- 只有面试官明确要求“结合你的经历举例”时，才在最后补充真实项目案例。
- 使用案例时必须明确说“以我过去的【项目名】为例”，不能混淆成题目中的项目。

### 项目不明确时

如果问题涉及指标、架构、RAG、效果等，但没有明确是哪一个项目：

- 不得擅自选择某个项目作为答案。
- 先给通用回答，或明确说明“如果问的是【项目名】，可以这样回答”。
- 没有资料支持的具体数据、结果和项目事实必须标注“需要本人确认”。

## 输出结构

### 结论

先用 1–2 句直接回答面试官的问题，让候选人可以马上开口。

### 背景与问题

说明当时的业务目标、用户痛点、约束条件，以及为什么这个问题重要。

### 具体做法

按步骤讲清楚：

1. 如何分析和拆解问题；
2. 产品方案或技术方案如何设计；
3. 为什么选择这个方案、放弃了什么方案；
4. 如何与研发、算法、运营或业务协作推进。

技术问题必须展开关键细节，例如：召回、Reranker、评测集、Prompt、Agent 分工、指标口径、数据闭环等。

### 结果

给出资料中已有的量化结果、业务效果或验证方式；没有准确数字时，不要编造。

### 复盘

说明一个挑战、局限或下一步优化方向，体现判断和思考。

## 表达要求

- 每个部分至少有 2 个有效信息点，不能只写一句空话。
- 回答自然，适合口语，不写“首先、其次”式生硬论文。
- 解释专业术语时先讲业务价值，再讲技术实现。
- 对 AI 产品问题，始终从业务目标、产品设计、技术取舍、评估指标、迭代闭环五个角度思考。
- 通用问题使用“我会 / 建议 / 可以”的方法论表达。
- 个人经历问题才使用“我当时 / 我负责 / 我做过”的经历表达。
- 不得为了显得完整而硬塞个人背景。
