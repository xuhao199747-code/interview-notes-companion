# 面试资料伴侣第一期设计

## 目标

在 macOS 桌面端持续监听允许录制的面试音频。面试官完成一个问题后，应用应在 2 到 3 秒内优先展示用户 Markdown 中的高相关答案；资料不足时，再用 LLM 按用户上传的回答 Skill 补充。用户本人回答不得触发检索或生成。

## 固定技术选型

| 能力 | 第一期开通与实现 |
| --- | --- |
| 实时转写 | 已接入的豆包流式 ASR，保持现有采音和 WebSocket 链路 |
| 自动断句 | 豆包服务端 VAD 为主，本地语义和静默状态机为兜底 |
| 本人过滤 | 腾讯云 VoicePrintEnroll 与 VoicePrintVerify |
| 文档答案 | 本地 Markdown：问题资料优先于知识库 |
| 回答格式 | 用户上传的 Answer Skill，只控制写法，不作为事实来源 |
| LLM | 独立 OpenAI 兼容 API；DeepSeek 或豆包方舟均可配置 |

腾讯云只用于声纹注册和验证，不替换豆包 ASR。密钥仅保存在本机 Node/Electron 侧，渲染页面只显示掩码。

## 运行数据流

```text
音频输入
  ├─ 豆包 ASR：临时文本和最终句
  └─ 本地语音活动切片
       └─ 腾讯云声纹验证：本人 / 非本人 / 不确定
            ↓
      断句与问题状态机
            ↓
  资料召回 → 相关性与覆盖度判断 → 回答路由 → 页面
```

监听只在用户点击结束时关闭；单题提交、LLM 生成和声纹验证都不能停止监听。

## 断句状态机

- 豆包返回最终句时立即提交。
- 仅有临时文本时，本地在语义完整的疑问句后静默 1.2 秒提交。
- 普通完整句在静默 2.2 秒提交。
- 未完成结尾（如“然后”“比如”“因为”“我想问一下”）继续合并。
- 已有有效文本但静默达到 3.5 秒，强制提交，避免永久卡住。
- 已提交后再次检测到非本人语音，创建下一题；上一题必须归档。
- 短追问（“为什么”“展开讲讲”“具体怎么做”）创建新题，并携带上一题问题和来源内容。

## 说话人与声纹规则

- 声纹结果为本人：显示“已忽略本人回答”，不检索、不生成。
- 声纹结果为非本人：完整问题或追问进入回答流程。
- 声纹结果不确定：仅明显疑问句可触发，并显示低置信度。
- 重叠语音：默认不自动触发，避免用户自身语言被误识别成问题。
- 声纹录入必须真实调用腾讯云创建 VoicePrintId；本地只保存档案 ID、样本元数据和掩码配置。
- 声纹样本不足、腾讯服务未开通、验证失败时，不得显示“声纹过滤已启用”。

## 回答路由

1. 问题资料中的直接答案为最高优先级。
2. 知识库中的事实片段为第二优先级。
3. 多段证据足够时，LLM 只能整理这些资料，不得添加未经资料支持的项目事实。
4. 资料相关但覆盖不完整时，先展示资料，并标记 LLM 为“补充生成”。
5. 无资料命中时，LLM 可给通用建议，但必须标记“资料未命中”。

召回采用关键词、标题、正文和语义相似度共同排序。判断是否可回答时必须检查问题关键要素：例如“有几个 Agent”必须有数量证据，单纯提到 Agent 的段落不能视为直接命中。

## 延迟预算与降级

| 阶段 | 目标 |
| --- | --- |
| 断句 | 1.2 至 3.5 秒，取决于语义完整度 |
| 本地候选召回 | 小于 300 ms |
| 高置信资料答案上屏 | 最终问题确认后小于 500 ms |
| LLM 首段 | 最终问题确认后 1.5 至 2.5 秒 |

在面试官说话期间可做预检索。问题确认后先显示高置信资料，再并行请求 LLM 流式补充。LLM 慢、失败或旧题晚到均不能阻塞或覆盖新题。

## 设置与可观测性

设置页分为资料管理、语音识别、本人声纹过滤、回答生成四个区域。每项能力都有独立的保存和测试状态。

主页面必须可见：音频包数量、豆包连接/临时文本/最终句、声纹判定、当前题、资料命中来源及相关度、LLM 首字耗时和错误信息。每次未出答案时，用户能定位故障发生在采音、转写、断句、声纹、检索或 LLM 中的哪一层。

## 第一期开工顺序

1. 自动断句和连续多题状态机。
2. 低延迟回答路由和来源/置信度展示。
3. 腾讯云声纹配置、样本注册、验证测试。
4. 声纹接入实时片段并实现本人过滤。
5. 全链路诊断、故障降级和桌面端验收。

## 第一期开通前置条件

- 用户确认豆包 ASR 保持现有配置。
- 用户在腾讯云控制台开通说话人验证能力，并允许本地应用使用其腾讯云密钥调用 VoicePrintEnroll/VoicePrintVerify。
- 用户在设置页录入至少三段正常语速的本人声音样本。

## 验收场景

1. 面试官完整提问后，应用自动显示资料答案和 LLM 补充，不需要停止监听。
2. 面试官卡顿后继续说，应用合并为同一题；卡顿超过最长等待时提交已有内容。
3. 一题结束五秒后再次提问，应用自动创建下一题，上一题不被覆盖。
4. 用户连续回答时，声纹命中且不创建新题。
5. 面试官短追问能继承上一题上下文。
6. 豆包、声纹、检索、LLM 任一层失败时，主页面显示准确故障状态。
