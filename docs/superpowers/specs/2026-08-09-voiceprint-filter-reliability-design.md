# 声纹过滤可靠性设计

## 目标

让桌面端只对被腾讯云明确判为“非本人”的完整面试问题触发检索和回答；本人、未知、超时和重叠语音均不自动触发。

## 决策

采用严格过滤（fail closed）：声纹结果不确定时不生成答案。这样可能漏掉一次面试官问题，但不会把候选人的回答误作为问题处理，符合产品的核心约束。

## 数据流

1. 录入使用一段 6 秒本人语音创建腾讯云档案。
2. 验证必须重新录制独立的 4 秒样本。只有腾讯云 `Decision === 1` 时，才保存 `voicePrintVerified: true`。
3. 桌面监听保留有限 PCM 环形缓冲区；ASR 产生最终句时，按该句完成时刻截取最近的短片段送声纹验证。
4. 门控只接受三种结果：`self` 忽略、`other` 且完整问题才允许、`unknown`/`overlap` 一律保持等待且不检索。
5. UI 明确显示“过滤已启用 / 未验证 / 判定不确定未触发 / 本人已忽略 / 面试官问题已检索”。

## 范围

- 修复验证失败错误持久化为已验证的问题。
- 分离注册和验证样本。
- 对豆包和腾讯 ASR 使用一致的最终声纹门控。
- 为失败、未知、超时和成功路径添加自动化测试。

## 非目标

- 不以腾讯 ASR 的临时 Speaker ID 作为永久身份。
- 不修改已验证可用的豆包语音转写协议。
- 不保存原始声纹样本到本机；只保存腾讯云档案 ID 和已验证状态。
