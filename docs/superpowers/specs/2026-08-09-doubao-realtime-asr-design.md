# 豆包实时语音识别接入设计

## 目标

在 Mac 桌面客户端中新增“豆包 / 火山引擎”实时语音识别提供商。用户可在设置中选择腾讯云或豆包；选择豆包并保存有效凭据后，桌面监听将把本机采集到的 16 kHz PCM 音频发送至豆包流式语音接口，并将最终识别文本用于检索与回答。

## 范围

- 新增豆包语音配置：App ID、Access Token、资源 ID（cluster）和可选 WebSocket 地址。
- 语音识别提供商选择扩展为：浏览器、腾讯云 V2、豆包流式识别。
- Electron 主进程持有豆包凭据、建立 WebSocket，并把结构化识别结果发给渲染进程。
- 渲染进程沿用既有桌面音频采集和检索逻辑；豆包没有可靠说话人编号时，不自动触发“忽略本人”的过滤，而是明确显示该限制。
- 新增“测试豆包连接”按钮及可操作的错误提示。

## 不在本次范围

- 声纹样本自动匹配。它需要单独开通的声纹验证能力和服务端存储，不能由普通 ASR 代替。
- 替换现有 DeepSeek LLM。现有 OpenAI 兼容 LLM 配置可在之后单独接入豆包模型。
- 将会议应用的系统输出自动捕获。用户仍需选择麦克风或虚拟音频输入设备。

## 方案比较

1. 保持腾讯云：改动最少，但当前账户真实握手已返回 4004，无法使用。
2. 接豆包流式 ASR（采用）：独立账户与计费，适合实时语音转文字，能复用当前 PCM 音频链路。
3. 仅使用浏览器 Web Speech：无需密钥，但识别质量和稳定性受浏览器服务影响，且无法承担桌面会议音频路由。

## 架构与数据流

1. 设置页把不含明文密钥的配置状态返回到渲染进程；密钥只写入本地 `.local/asr-config.json`，仅 Node/Electron 主进程读取。
2. 点击“开始桌面监听”后，渲染进程从选中的音频输入采集音频，经 AudioWorklet 转成 16 kHz 单声道 PCM。
3. Electron 主进程按当前提供商创建 Tencent 或 Doubao 会话，音频二进制由 IPC 转发至对应 WebSocket。
4. 会话把最终转写标准化成 `{ type: 'result', sentence: { sentence, sentence_type, speaker_id } }`。腾讯云保留其 speaker_id；豆包使用 `speaker_id: -1`。
5. 渲染进程仅在腾讯云且用户已确认本人 Speaker ID 时过滤本人；豆包的最终文本直接进入既有问题确认、知识库检索与 LLM 回答链路。

## 错误处理与可见状态

- 未填写任何必填豆包字段：保存失败并指出缺失项。
- 豆包 WebSocket 鉴权或资源未开通：测试按钮显示服务端错误原文的安全摘要。
- 桌面端选择豆包但当前是浏览器页面：提示必须从 Electron 启动。
- 豆包连接断开：停止发送音频、恢复“开始监听”按钮，并显示可重试状态。

## 验证

- 单元测试覆盖配置校验、无敏感字段泄露、请求头/首帧构造、响应规范化及结果过滤分支。
- 运行完整 Node 测试和语法检查。
- 用户填入真实豆包凭据后，点击测试连接必须获得成功响应；随后在桌面端用选定音频设备验证最终文字上屏并触发检索。

## 安全与限制

- 不在页面、日志、测试输出或 API 响应中回显 Access Token。
- 豆包服务也需要用户自行开通并计费；接入不代表免费或自动获得额度。
- 说话人分离和声纹验证是不同能力：本次不会将“声音样本已录入”描述为自动声纹识别已生效。
