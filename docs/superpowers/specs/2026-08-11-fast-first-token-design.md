# Fast First Token Design

## Goal

让同一篇面试回答在模型返回第一个字时立即显示，并通过缩小首轮上下文缩短首字等待；前文只追加、不替换。

## Design

检索、项目路由、资料命中顺序和回答范围保持不变。仅在发送给 LLM 时使用首读预算：最多保留两条最强命中资料、每条最多 900 字；个人经历和上一题上下文继续按既有范围规则传递，但分别限制为 700 和 400 字。回答 Skill 仍使用，但限制为 1800 字，避免长模板推迟首包。

前端继续逐个 SSE delta 追加到同一个答案字符串，并在每个包含文本的响应帧后渲染。不会创建“第一版/第二版”，也不会替换已经显示的内容。

## Constraints

- 不改变知识库检索、项目判定、术语纠错或用户资料。
- 不修改 LLM 服务商、模型或 API 配置。
- 保持 DeepSeek `thinking: disabled`。
- 保持流式 SSE 接口兼容。

## Verification

- 上下文构建函数能按首读预算裁剪为两条短资料。
- API 仍以 `stream: true` 请求模型且转发每个 delta。
- 前端遇到首个 delta 时立即写入当前回答，后续只追加。
