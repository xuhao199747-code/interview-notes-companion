# 轻便式回答编排设计

## 目标

在不改变现有“手动开始监听、手动结束或静音超时提交、随后生成答案”的主流程下，增强问题的项目路由、资料证据筛选和 LLM 回退。

## 不变的行为

- 录音开始和题目结束仍由现有界面控制；本设计不改变音频采集、超时或热键。
- 本地资料仅用于检索和引用，绝不创建或保存任何固定的“通用答案”。
- 资料证据不足时，仍调用用户已配置的 LLM；界面不显示伪造的本地引用。
- 回答规则、回答 Skill 和术语表继续沿用现有边界：规则约束范围，Skill 约束表达，术语表只帮助理解。

## 轻便编排层

现有 `runSearch()` 已完成项目范围判断、资料过滤、混合检索和回答请求。新增纯函数编排层只接收这些候选并产出：

- `evidence`：最多三条、可直接支撑回答的资料段落；
- `mode`：`grounded`（有可靠本地证据）或 `llm-only`（没有可靠证据）；
- `reason`：用于界面说明为何采用该模式。

候选只有在词面或混合检索具有明确命中，或语义分数达到保守阈值且标题/项目与问题相关时，才进入 `evidence`。没有合格证据时不向 LLM 传入无关资料，也不渲染“文档库参考”。

## 数据边界

语义索引服务端和渲染端都只处理知识资料。`skill` 与 `converter-skill` 都被排除，避免资料转换说明污染问答检索。

## 呈现与速度

- 编排是本地同步排序和裁剪，不增加网络请求。
- 语义检索仍保留现有 1.5 秒上限；超时立即走已有的关键词/LLM 路径。
- 有证据时显示精简引用卡；无证据时显示“未找到可靠本地资料，已使用 LLM 通用生成”，不展示无关资料。

## 验证

- 回答 Skill、资料转换 Skill 不会进入服务端索引。
- 命中低相关资料时，结果进入 `llm-only`，不会作为引用或 LLM 上下文。
- 命中项目资料时，最多选择三条证据，优先项目/标题精确命中和混合命中。
- 既有路由、项目范围和检索测试继续通过。
