# 公开代码与本机个人资料边界

本项目可以开源代码，但运行时的候选人资料必须只保存在本机。

## 可提交到 GitHub

- `src/`、`electron/`、`app.js`、`server.js`、测试和架构文档；
- `assets/AI产品经理回答规则.md`：通用回答范围与事实约束；
- `assets/AI产品经理面试完整口述回答Skill-通用版.md`：通用口述组织方式；
- 通用 AI 产品经理术语、空白示例资料和空白个人表达偏好模板。

公开层不能出现真实姓名、公司、项目、飞书链接、客户、指标、Access Token、SecretId 或 SecretKey。

## 只保存在本机

- “资料管理”中上传的全部 Markdown：简历、项目资料、逐字稿、个人知识库；
- 当前回答 Skill 的个人版及任何个人表达补充；
- 术语表中的私有项目别名；
- ASR、LLM、腾讯云、豆包等 API 配置；
- 本地语义索引、下载与导出文件。

这些数据由桌面应用保存到本机数据目录和 `.local/`，不由仓库提供，也不上传到 GitHub。

## 回答 Skill 的两层使用方式

运行时保持以下优先级：

1. 内置公开回答规则：规定题型范围、真实性和口述质量；
2. 本机回答 Skill：规定个人口吻和回答偏好；
3. 当前题命中的本机 Markdown：唯一的个人经历、项目和指标事实来源。

个人事实不得写入 Skill。这样通用题不会被个人项目强行污染，项目题仍能用命中的本机资料回答。当前版本的本机回答规则继续保存在 `answer-rules.json`，因此不需要迁移现有文件，也不会影响回答效果或速度。

## 使用方式

1. GitHub 用户使用公开通用 Skill 和空白模板；
2. 你本人继续通过“资料管理”上传真实 Markdown；
3. 如需设置个人口吻，以 `examples/personal-style.private.template.md` 为参考，填写后通过“回答规则”上传到桌面应用；
4. 不要把 `private/`、`.local/` 或桌面应用数据目录加入 Git。

## 公开前检查

1. 检查 `git status`，确认没有个人 Markdown 或密钥文件待提交；
2. 检查 `git ls-files`，确认只保留通用 Skill 和脱敏示例；
3. 不公开当前私有仓库的历史；创建新仓库或过滤历史后再推送；
4. 在新 macOS 用户目录用示例资料启动一次，确认应用不依赖你的本机数据。
