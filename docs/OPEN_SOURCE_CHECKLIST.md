# 开源检查清单

当前仓库包含个人资料和项目知识库，不能直接切换为公开仓库。公开前必须创建一个干净的发布分支或新仓库，而不是直接把当前工作分支设为 public。

## 必须保留

- Electron 壳、一次性问题识别、快捷键、ASR/LLM 通用适配接口；
- 本地 Markdown 导入/编辑/删除/下载能力；
- 检索、回答范围、上下文预算和空状态逻辑；
- 不含真实信息的示例 Markdown、示例 Skill、示例术语表；
- `.env.example` 与配置说明，不含真实密钥。

## 必须移除或替换

- 根目录所有个人简历、项目知识库、面试逐字稿和真实术语表；
- `assets/` 内的个人回答 Skill、规则和面试材料；仅保留明确标注“通用开源版”的 Skill 与不含个人信息的通用规则；
- `docs/superpowers/` 中含真实截图、项目细节或内部排障记录的文件；
- Git 历史中的密钥、Access Token、真实 App ID 和导出资料；
- 任意自动部署整个仓库的工作流。GitHub Pages 工作流已删除；公开演示应只发布单独的脱敏 `demo/` 目录。

## 发布前验证

1. 用 `git grep -nEi 'AKID|Access Token|SecretKey|api[_-]?key'` 检查并人工确认结果。
2. 用 `git ls-files` 确认没有个人 Markdown、导出文件、数据库或模型缓存。
3. 在全新 macOS 用户目录启动，确认没有依赖旧的 `userData`。
4. 用样例资料跑导入、删除、下载、快捷键、一次性录音和 LLM 空状态回归。
5. 单独创建 public 仓库或使用过滤后的 orphan 分支；不要将当前私人 Git 历史直接公开。
